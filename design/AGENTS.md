# 공통 디자인 작업 지침

- 시각 기준은 현재 웹 화면입니다. 변경 전 `README.md`, 해당 웹 화면·CSS, `system.json`의 화면 계약을 읽습니다.
- 원본은 `tokens.json`, `web-aliases.json`, `assets/vectors.json`, `fonts/manifest.json`·글꼴 파일, `system.json`입니다. 생성된 웹·Kotlin·리소스 사본은 직접 편집하지 않습니다.
- 웹·앱은 같은 시각 값을 사용합니다. 시각적 `platformOverrides`나 앱 전용 브랜드·팔레트·글꼴·모서리·홍보 장식·화면 계층을 추가하지 않습니다.
- 양쪽에서 같은 역할의 타이포그래피·컴포넌트·레이아웃 토큰을 사용합니다. 숫자가 같은 글자 크기 토큰으로 의미 기반 토큰을 대신하지 않습니다.
- 책 로고·아이콘 도형과 Pretendard 버전·굵기·라이선스를 유지합니다. 글꼴 변경 시 공식 출처, 웹/앱 형식, manifest 체크섬, 라이선스를 확인합니다.
- 웹 구조 변경은 Compose 구현과 화면 계약에도 반영합니다. 생성기는 참조를 검사하고 값·자산·문구를 생성합니다. 화면 트리를 변환하거나 비교하지는 않습니다.
- 반응형은 공통 `layout.*`를 사용합니다. 웹은 Vite의 `design(layout.name)`, 앱은 대응하는 `DesignTokens.Layout` 값을 사용합니다.
- 생성은 `node design/scripts/generate.mjs`, 읽기 전용 검사는 `--check`입니다. 빌드가 재생성하기 전에 검사합니다. 생성기·스키마 변경 시 관련 테스트를 실행합니다.
- 화면 일치를 보고하기 전, 같은 계정·데이터·상태로 웹·앱의 휴대폰·태블릿 화면을 비교합니다. 캡처 크기와 미검증 플랫폼을 기록합니다.
- OS 안전 영역·키보드·권한/기기 창·보이지 않는 추가 터치 범위·시스템 PiP/ReplayKit·네이티브 렌더러 차이는 허용합니다. 공통 화면 계층을 유지하고 실제 실행 검증의 한계를 명시합니다.
