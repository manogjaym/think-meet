# 인프라 검증 기준

인프라 생성과 서버 성능은 따로 검증합니다. 아래 로컬 검사는 서버 코드 없이 실행할 수 있습니다.

## 로컬 검증

프로젝트 최상위에서 실행합니다.

```bash
./infra/scripts/validate.sh --init
```

검사 항목은 다음과 같습니다.

- 통합 테스트: 기존 AWS 리소스와 서버 전달 출력 보존, 운영과 상태 분리
- 테스트 노드: 앱·미디어의 최소·희망·최대 수가 각각 1대
- 단일 노드 컨트롤러: 복제 수·PDB·CPU 예약 여유
- 배포 의존성: 서버 소스·이미지·앱 리소스 없이 실행 가능
- 리소스 연결: 직접 참조, Helm 생성 순서, 제한된 RBAC
- 외부 접속: 서버 없이 로드밸런서·대상 그룹 생성
- Terraform: 구문·공급자 스키마·잠금 버전

## AWS 적용 후 검증

다음 항목은 AWS 적용 후 확인합니다.

- EKS 노드·기본 애드온, 비공개 API 접근
- NAT·VPC Endpoint 경로, 보안 그룹
- ACM·DNS·CloudFront, 로드밸런서·WAF 연결
- 서버 배포 전 대상 그룹이 비어 있는지 여부

Aurora reader 장애 조치, RDS Proxy TLS, Redis 복제·인증, 백업 복원, 경보 전송은 별도 환경에서 시험합니다. 리전별 인스턴스 가용성과 서비스 할당량은 실제 계획 시 확인합니다.

동접 50명 이상이나 운영 목표 인원의 수용 여부는 서버 담당자가 부하 시험으로 측정합니다. 방 구성·화질·구독 수·TURN 비율을 함께 기록합니다. EC2 사양만으로 처리량을 보장할 수 없습니다.
