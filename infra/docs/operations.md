# 인프라 운영

AWS 리소스·EKS 기본 구성·인프라 애드온을 관리합니다. 서버 배포·SQL 스키마·미디어 프로세스·웹 파일은 서버 담당자가 관리합니다.

## 상태와 접근

Terraform 계획·상태에는 인증값이 포함될 수 있습니다.

- 상태·계획 파일은 Git에 넣지 않습니다.
- 운영과 원격 backend를 쓰는 테스트는 KMS 암호화·IAM 접근 제한·잠금을 유지합니다.
- 테스트 기본 상태는 `infra/terraform/test/terraform.tfstate` 하나입니다. 안전하게 보관·백업·인계합니다.
- 테스트 원격 상태 키는 `think-meet/test/terraform.tfstate` 하나입니다.
- bootstrap의 로컬 상태도 별도로 안전하게 보관합니다.

EKS 관리 API는 기본 비공개입니다. 테스트에서 `eks_public_access_cidrs`를 지정하면 그 범위에만 공개 API 접근을 허용합니다. 노드·애드온 실행기는 VPC 또는 연결된 사설망에서 DNS·TCP 443에 접근할 수 있어야 합니다. 플랫폼 실행 IAM 역할이 바뀌면 자동 등록되는 관리자도 바뀔 수 있으므로 계획과 `cluster_admin_arn`을 확인합니다.

## 인증값

Redis 토큰은 `random_password` 상태의 값을 재사용하며 Secrets Manager와 ElastiCache에 같은 값을 적용합니다. 상태 삭제나 강제 교체로 재생성하지 않습니다. 기존 토큰을 이어받을 때는 `redis_auth_tokens`를 사용하고 서버 담당자와 교체 시점을 맞춥니다.

Aurora 관리자 암호는 AWS가 관리합니다. 앱·마이그레이션·런타임 Secret은 저장 공간만 제공합니다. 값과 SQL 계정은 서버 담당자가 관리하며, 실제 값을 등록한 뒤 RDS Proxy를 앱 Secret으로 전환합니다.

## 노드·애드온 변경

통합 테스트는 한 폴더에서 `terraform apply`로 변경합니다. EKS 업데이트 중 임시 노드가 추가될 수 있습니다. 노드 교체·축소 전에는 서버 담당자와 시간을 맞추고 작업을 이동하거나 종료합니다. 단일 노드 테스트는 유지보수 중 중단될 수 있습니다. 미디어 노드는 수동 조정하고 Autoscaler의 조정 권한은 앱 노드로 제한합니다.

애드온 차트·이미지·IAM 정책은 호환 버전으로 함께 바꿉니다. 잠금 파일을 유지하고 `validate.sh --init`을 실행한 뒤 실제 계획을 검토합니다.

## 로드밸런서

Terraform이 ALB·NLB·리스너·대상 그룹·WAF·DNS를 관리합니다. 서버 배포 도구는 출력된 대상 그룹 ARN으로 서버를 등록합니다. 별도 Ingress·Service가 같은 로드밸런서를 중복 생성하지 않도록 소유권을 구분합니다.

서버 배포 전에는 대상 그룹이 비어 있는 것이 정상입니다. 배포 후에는 대상 상태·상태 확인 경로·보안 그룹·포트·인증서를 확인합니다.

## 백업과 폐기

Aurora 백업은 35일, Redis 스냅샷은 7일 보관합니다. 별도 클러스터·그룹에서 복구를 시험한 뒤 서버 연결을 전환합니다. 계획에서 S3 버전·KMS 키·DB·캐시 삭제 보호도 확인합니다.

폐기할 때는 다음 순서를 지킵니다.

1. 운영·테스트의 backend 키를 확인합니다.
2. 서버 대상 등록을 해제하고 필요한 백업을 보관합니다.
3. 절차에 따라 로드밸런서·데이터 삭제 보호를 해제합니다.
4. 해당 환경에만 적용합니다. 상태 저장소와 KMS를 먼저 삭제하지 않습니다.
